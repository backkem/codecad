What runs where

Server
Runs scripts in a sandbox, builds solids with the kernel, checks them, renders PNGs (working and path traced), writes prebaked scenes, DWG and PDF.
Browser
Opens DWG, draws and edits in 2D through the same API, and shows prebaked 3D scenes in both render modes. The app fetches the solid kernel on the first call that needs it and then builds parts in the page; the example pages show prebaked scenes and never fetch it.
Direction
Models as the input to fabrication: 3D printing and CNC. Not a feature today.

DWG in the browser

Opens .dwg files (R13–R2018) with infinite vector zoom. Vello/WebGPU rendering, egui CPU fallback.

3D in the browser

Prebaked scenes open without a kernel: orbit, zoom, and switch between the working render and the path-traced presentation render. WebGPU only.

Scriptable API

Every operation is a call like cad.addLine() or cad.extrude(). Drive it from the console, your own code, or a language model.

Real-time sync

An optional Rust server syncs edits across browsers (Yrs CRDT over WebTransport) and runs JS scripts in a Wasmtime sandbox.

Draw with code

Plain JavaScript calls. Pan and zoom the result below.

// Plate flange DN80 PN16: bolt pattern on a pitch circle
cad.addLayer("OUTLINE", { color: [255, 255, 255] })
cad.addLayer("CENTER", { color: [255, 0, 0], linetype: "Center" })

cad.addCircle([0, 0], 100,  { layer: "OUTLINE" })   // Ø200 outside
cad.addCircle([0, 0], 45.5, { layer: "OUTLINE" })   // Ø91 bore
cad.addCircle([0, 0], 80,   { layer: "CENTER" })    // Ø160 PCD

// One bolt hole, then a polar array of 8
const a = Math.PI / 8
const hole = cad.addCircle([80 * Math.cos(a), 80 * Math.sin(a)], 9, { layer: "OUTLINE" })
cad.array(hole, { polar: { center: [0, 0], count: 8 } })

cad.dimDiameter({ center: [0, 0], radius: 100 }, { angle: 30 })
